# hough_transform —— 霍夫变换（直线 + 圆检测）

## 1. 功能概述

两路独立的检测：

1. **直线**：`Canny` 边缘 → `HoughLinesP`（概率霍夫）→ 在原图上画红色线段，
   统计总数、长直线数、平均角度、平均长度；
2. **圆**：高斯模糊 → `HoughCircles`（HOUGH_GRADIENT）→ 画绿圈 + 红圆心，统计数量与半径分布。

输出**两张独立的图**（不像其他模块合成一张网格），因为直线与圆的测试样本通常是不同图片。

## 2. 算法清单

| 算法 | 检测对象 | 参数空间 | 特点 |
|------|---------|---------|------|
| `HoughLines`（标准） | 直线 | `(ρ, θ)` 二维累加器 | 输出无限长直线，需自己算端点。**本模块未使用** |
| **`HoughLinesP`（概率）** | 线段 | `(ρ, θ)` + 端点搜索 | **本模块使用**。直接输出线段两端点，且只随机采样部分边缘点，快得多 |
| `HoughCircles`（HOUGH_GRADIENT） | 圆 | `(x, y, r)` 三维累加器（用梯度方向降维） | 用**梯度方向投票**把 3D 搜索降到 2D，是速度的关键 |

### 2.1 霍夫变换的核心思想

**图像空间的点 ↔ 参数空间的曲线**。

- 直线：过图像空间某点的所有直线，在 `(ρ,θ)` 参数空间是一条正弦曲线。**共线的点**
  对应的曲线会**交于同一点**——累加器在该点出现峰值。
- 圆：过某点的所有圆，在 `(x,y,r)` 空间是一个圆锥面。OpenCV 先用 Sobel 算梯度方向，
  圆心必在梯度方向的射线上，于是只需沿射线投票（2D 累加器 + r 维），大幅降维。

### 2.2 为什么用 HoughLinesP 而不是 HoughLines

| 对比项 | HoughLines | HoughLinesP |
|--------|-----------|-------------|
| 输出 | `(ρ, θ)`，直线无限长 | `(x1,y1,x2,y2)`，真实线段 |
| 速度 | 慢（全边缘点投票） | 快（随机采样 + 最小长度约束） |
| 易用性 | 需自己反算端点并裁剪 | **直接可画** |
| 适用场景 | 需要完整直线方程 | **绝大多数实际场景** |

## 3. 运行

```powershell
cd build\algorithms

.\hough_transform.exe                                                     # 默认 sudoku + smarties
.\hough_transform.exe ..\..\data\sudoku.png ..\..\data\smarties.png       # 显式指定
```

构建：

```powershell
.\build.ps1 -Target algorithms -Module hough_transform
```

## 4. 输入 / 输出

**输入**

| 参数 | 位置 | 默认 | 说明 |
|------|------|------|------|
| `argv[1]` | 直线测试图 | `../../data/sudoku.png` | 含大量规则直线的图 |
| `argv[2]` | 圆测试图 | `../../data/smarties.png` | 含大量圆形物体的图 |

- 直线图长边 > 900 缩放至 900；圆图长边 > 700 缩放至 700。
- 读取失败时合成兜底图（两条交叉线 / 6 个圆），保证可跑。

**输出**

| 文件 | 内容 |
|------|------|
| `out/algorithms/hough_lines.png` | 3 格：input / Canny / HoughLinesP（红线） |
| `out/algorithms/hough_circles.png` | 2 格：input / HoughCircles（绿圈 + 红心） |

**stdout**

```
[lines] ../../data/sudoku.png
lines total=58  long(>100px)=23  meanAng=1.8 deg  meanLen=342.1 px
[circles] ../../data/smarties.png
circles=12  meanR=28.4  maxR=31.0
```

## 5. 参数表

### 5.1 直线（HoughLinesP）

| 参数 | 代码位置 | 默认 | 影响 |
|------|---------|--------|------|
| `Canny` 低阈值 | `Canny(gray, edges, 50, 150)` | `50` | ↑ 边缘更少更干净，↓ 边缘更多更碎 |
| `Canny` 高阈值 | 同上 | `150` | 建议 **2:1 ~ 3:1** |
| `rho`（距离分辨率） | `HoughLinesP(edges, lines, 1, CV_PI/180, 80, minLen, 20)` | `1` px | ↓ 精度高但累加器大、慢 |
| `theta`（角度分辨率） | 同上 | `CV_PI/180`（1°） | ↓ 精度高但慢 |
| `threshold`（投票阈值） | 同上 | `80` | **最重要的参数**。↑ 只留最强直线，↓ 检出更多（含伪直线） |
| `minLineLength` | 同上（形参 `minLen`） | `40` | 短于此长度的线段丢弃 |
| `maxLineGap` | 同上 | `20` | 同一直线上间隙小于此值的两段会被**合并** |

### 5.2 圆（HoughCircles）

| 参数 | 代码位置 | 默认 | 影响 |
|------|---------|--------|------|
| 预模糊 | `GaussianBlur(gray, gb, Size(9,9), 3.0, 3.0)` | 9×9, σ=3 | **必要的**。HoughCircles 对噪声敏感，不模糊会检出大量假圆 |
| `dp`（累加器分辨率） | `HoughCircles(gb, circles, HOUGH_GRADIENT, 1.0, 40, 100, 30, 20, 200)` | `1.0` | `dp=1` 与输入同分辨率；`dp=2` 累加器减半（快，但精度降） |
| `minDist` | 同上 | `40` | 两圆心之间的最小距离，**防止重复检测同一个圆** |
| `param1` | 同上 | `100` | 传给内部 `Canny` 的**高阈值**（低阈值自动取一半） |
| `param2` | 同上 | `30` | **累加器阈值**，最重要的参数。↓ 检出更多圆（含假圆），↑ 只留最确定的 |
| `minRadius` | 同上 | `20` | 半径下限，0 = 不限 |
| `maxRadius` | 同上 | `200` | 半径上限，0 = 不限 |

> **`param2` 调参口诀**：先用较小值（如 10）看能检出多少，再逐步调大到假圆消失。
> 通常 `param2` 在 **20~50** 之间。`minRadius`/`maxRadius` 能给就给，**能极大减少假圆**。

## 7. 结果怎么读

### 7.1 直线指标

| 指标 | 定义 | 判读 |
|------|------|------|
| `lines total` | 检出的线段总数 | 与图复杂度相关，不是越多越好 |
| `long(>100px)` | 长度 > 100 px 的线段数 | **真正的结构线**。sudoku 上应该接近实际网格线数 |
| `meanAng` | 长直线的平均角度（度） | sudoku 上应接近 `0°` 或 `90°`（网格是正的水平/垂直）。**如果 meanAng 是乱的，说明检出的多是噪声线段** |
| `meanLen` | 长直线的平均长度（px） | sudoku 上应接近图像边长 |

**排错**：

| 现象 | 原因 / 解决 |
|------|-----------|
| 检出线段成百上千、密密麻麻 | `threshold` 太低。从 80 往上调（120/150） |
| 一条线被拆成好几段 | `maxLineGap` 太小。调大到 30~50 |
| 完全检不出 | `Canny` 阈值太高把边缘吃掉了，或 `threshold` 太高 |
| meanAng 毫无规律 | 图上本来就没有主导方向的直线，或 `minLineLength` 太小放进了噪声 |

### 7.2 圆指标

| 指标 | 定义 | 判读 |
|------|------|------|
| `circles` | 检出的圆数量 | 与图中实际圆数对比 |
| `meanR` | 平均半径 | smarties 上糖豆大小接近，meanR 与 maxR 应**很接近** |
| `maxR` | 最大半径 | 若 `maxR` 远超 `meanR`，很可能检出了假的大圆 |

**排错**：

| 现象 | 原因 / 解决 |
|------|-----------|
| 一个真圆被套了 3、4 个圈 | `minDist` 太小。调到 ≥ 2×最大半径 |
| 检出几十上百个假圆 | `param2` 太低。从 30 往上调（40/50） |
| 真圆一个都没检出 | `param2` 太高，或 `minRadius`/`maxRadius` 限制了范围。先设 `0,0` 放开看 |
| 圆位置偏移明显 | `dp` 太大（累加器太粗）。设回 `1.0` |
| 背景纹理处全是圆 | 预模糊不够。加大 `GaussianBlur` 核与 σ |
