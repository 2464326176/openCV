# optical_flow —— 光流估计（稀疏 LK + 稠密 Farneback）

## 1. 功能概述

对**相邻两帧**估计运动场，两种主流方法各出一图：

- **稀疏光流（Lucas-Kanade 金字塔）**：只跟踪少量 Shi-Tomasi 角点，画箭头；
- **稠密光流（Farneback）**：为**每个像素**都算位移，输出 HSV 速度场 + 抽稀箭头场。

## 2. 算法清单

| 算法 | 类型 | 前提假设 | 输出 | 速度 | 适用 |
|------|------|---------|------|------|------|
| **Lucas-Kanade（金字塔）** | 稀疏 | ①亮度恒定 ②小位移 ③邻域运动一致 | 若干特征点的位移向量 | **快** | 实时跟踪、SLAM 前端、运动估计 |
| **Farneback** | 稠密 | 亮度恒定 + **邻域二次多项式展开** | 每像素 `(dx, dy)` | 慢 | 运动分割、视频插帧、动作识别 |

### 2.1 Lucas-Kanade 的三个假设

| 假设 | 数学表达 | 被打破时会怎样 |
|------|---------|--------------|
| **亮度恒定** | `I(x,y,t) = I(x+dx, y+dy, t+dt)` | 光照突变 → 跟踪失败 |
| **小位移** | 一阶泰勒展开 `I_x·u + I_y·v + I_t = 0` | 位移过大 → **用图像金字塔解决**（先粗后细） |
| **空间一致** | 邻域内所有像素共享 `(u,v)` | 该点恰在运动边界 → 该点跟踪失败 |

> 单个像素的 LK 方程 `I_x·u + I_y·v + I_t = 0` 有 2 个未知数却只有 1 个方程（**孔径问题**）。
> LK 的解法是**取一个邻域（如 21×21），假设邻域内运动一致**，于是有了超定方程组，
> 用最小二乘解出 `(u,v)`。这也是为什么 LK 必须跟踪**角点**（纹理丰富的点）——
> 平坦区域和纯边缘上方程退化，解不出来。

### 2.2 Farneback 的思路

用**二次多项式**局部逼近每个像素邻域的灰度分布，通过比较两个多项式系数
反解出位移。天然对每个像素都输出一个位移，所以是稠密的。

## 3. 运行

```powershell
cd build\algorithms

.\optical_flow.exe                                          # 默认 data/vtest.avi 第 5 / 15 帧
.\optical_flow.exe ..\..\data\vtest.avi 5 15                # 显式指定帧号
.\optical_flow.exe ..\..\data\vtest.avi 100 101             # 相邻帧（位移小，LK 更准）
```

构建：

```powershell
.\build.ps1 -Target algorithms -Module optical_flow
```

## 4. 输入 / 输出

**输入**

| 参数 | 位置 | 默认 | 说明 |
|------|------|------|------|
| `argv[1]` | 视频路径 | `../../data/vtest.avi` | 也可传**图片路径**（会走到合成运动分支） |
| `argv[2]` | 帧 A 序号 | `5` | `CAP_PROP_POS_FRAMES` |
| `argv[3]` | 帧 B 序号 | `15` | 与 A 的间隔越大，位移越大 |

**三级兜底**（保证任何环境都能跑通）：

1. 视频能打开 → 直接读两帧；
2. 视频打不开 → 读 `data/images/lena.jpg`，用 `warpAffine` 施加**已知的平移+轻微旋转**
   （`0.985, -0.035, 12.0 / 0.035, 0.985, -8.0`）合成第二帧；
3. 图片也没有 → 合成随机图 + 平移。

> 兜底分支 2 的运动是**人为已知**的，所以可以拿它来**核验光流是否正确**——
> 这是调试光流代码的好办法。

**输出**

| 文件 | 内容 |
|------|------|
| `out/algorithms/optical_flow_compare.png` | 5 格 3 列：frameA / frameB / LK sparse（红箭头+绿点）/ Farneback HSV / Farneback arrows |

**stdout**

```
LK tracked=287/300  meanVecLen=8.42 px
Farneback activeCells=1240  meanAng=-33.7 deg
```

## 5. 参数表

### 5.1 LK 稀疏光流

| 参数 | 代码位置 | 默认 | 影响 |
|------|---------|--------|------|
| 特征点数量 | `goodFeaturesToTrack(gp, p0, 300, 0.01, 10)` | `300` | 跟踪点上限 |
| `qualityLevel` | 同上 | `0.01` | 保留最强响应的 1% 以上 |
| `minDistance` | 同上 | `10` | 特征点最小间距（非极大抑制） |
| `winSize` | `calcOpticalFlowPyrLK(gp, gn, p0, p1, status, err, Size(21,21), 3)` | `21×21` | **局部邻域大小**。↑ 更鲁棒但对运动边界更敏感（违反空间一致假设） |
| `maxLevel` | 同上 | `3` | **金字塔层数**。位移大必须加大（每层把位移缩小一半） |
| `status` 输出 | 同上 | — | 每个点是否跟踪成功。**必须检查**，失败的点是垃圾值 |

### 5.2 Farneback 稠密光流

| 参数 | 代码位置 | 默认值 | 影响 |
|------|---------|--------|------|
| `pyr_scale` | `calcOpticalFlowFarneback(gp, gn, flow, 0.5, 3, 15, 3, 5, 1.2, 0)` | `0.5` | 金字塔缩放比，经典值 0.5 |
| `levels` | 同上 | `3` | 金字塔层数 |
| `winsize` | 同上 | `15` | 平均窗口大小。**↑ 更平滑更鲁棒，↓ 更精细但噪声多** |
| `iterations` | 同上 | `3` | 每层的迭代次数 |
| `poly_n` | 同上 | `5` | 邻域多项式展开的窗口，只能取 5 或 7 |
| `poly_sigma` | 同上 | `1.2` | 多项式展开的高斯 σ。`poly_n=5` → 1.2；`poly_n=7` → 1.5 |
| `flags` | 同上 | `0` | `OPTFLOW_USE_INITIAL_FLOW` / `OPTFLOW_FARNEBACK_GAUSSIAN` |

### 5.3 可视化

| 参数 | 代码位置 | 默认 | 说明 |
|------|---------|--------|------|
| HSV 的 Hue | `h = ang/360 * 180` | — | **方向**编码。OpenCV HSV 的 H 取值范围是 0~179 |
| HSV 的 Value | `v = 255 * mag / mmax` | — | **幅度**编码，按全场最大幅度归一化 |
| 箭头抽稀步长 | `const int step = 16` | `16` | 每 16 px 画一个箭头，否则密到看不清 |
| 箭头放大倍数 | `Point(x + v.x * 4, ...)` | `×4` | 位移太小看不清，画箭头时放大 4 倍 |
| 箭头显示阈值 | `if (d > 0.5)` | `0.5` px | 位移小于此值不画，避免静止区全是点 |

## 7. 结果怎么读

### 7.1 LK 指标

| 指标 | 定义 | 判读 |
|------|------|------|
| `LK tracked` | 成功跟踪的点数 / 总点数 | **比率 > 80% 算健康**。低于 50% 说明帧间位移过大或场景纹理不足 |
| `meanVecLen` | 成功点的平均位移长度（px） | 与帧间隔和物体速度对应 |

**tracked 比率低的排查**：

1. **帧间隔太大** → 位移超出 `maxLevel=3` 金字塔的处理能力。换相邻帧（如 `100 101`）试试，
   或把 `maxLevel` 加到 4~5。
2. **场景纹理不足**（白墙、天空）→ Shi-Tomasi 提不出好角点。降低 `qualityLevel` 到 0.001。
3. **光照变化** → LK 的亮度恒定假设被破坏。考虑先做直方图均衡化。

### 7.2 Farneback 指标

| 指标 | 定义 | 判读 |
|------|------|------|
| `activeCells` | 抽稀网格中位移 > 0.5 px 的格数 | 反映**运动区域占比**。静止背景下有运动物体 → 这个数不会太大 |
| `meanAng` | 所有有效格的平均角度（度，0=向右，逆时针为正） | 整体运动方向 |

### 7.3 HSV 速度场怎么读

**Hue（色相）= 方向，Value（明度）= 大小**：

| 颜色 | 方向（近似） |
|------|------------|
| 红 | 0°（向右） |
| 黄 | 60° |
| 绿 | 120° |
| 青 | 180°（向左） |
| 蓝 | 240° |
| 品红 | 300° |

**越亮 = 位移越大；越暗（接近黑）= 位移越小**（静止区）。

> **重要提醒**：HSV 图里的颜色**只表示方向，不表示"哪个物体"**。要判断运动物体在哪，
> 看的是**亮度**（Value）——亮的地方在动，黑的地方没动。

### 7.4 视觉检查清单

| 现象 | 说明 |
|------|------|
| LK 箭头方向整体一致 | 相机整体运动（或场景整体运动），正常 |
| LK 箭头在物体边界处方向突变 | 正确，这正是**运动分割**的依据 |
| Farneback 一片黑 | 两帧几乎无运动。加大帧间隔 |
| Farneback 满屏彩色噪点 | `winsize` 太小或场景纹理不足。调大 `winsize` 到 21/31 |
| 合成运动模式下 LK 箭头方向不统一 | 代码有 bug。合成运动是仿射变换，方向应当高度一致 |
