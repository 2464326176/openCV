# template_matching —— 模板匹配全方法 + 多尺度定位

## 1. 功能概述

遍历 OpenCV 的 **6 种 `matchTemplate` 方法**，各自在场景图上定位模板并画出匹配框，
再叠加一层**多尺度扫描**找出全局最优尺度与位置。

模板匹配是最朴素也最实用的目标定位手段：不需要训练、不需要特征点，
在**目标形变小、光照稳定**的工业场景里依然是首选。

## 2. 算法清单

| 方法 | 公式要点 | 最优值 | 归一化 | 特点 |
|------|---------|--------|--------|------|
| `TM_SQDIFF` | `Σ(T−I)²` | **最小** | 否 | 最直观。对**整体亮度缩放敏感** |
| `TM_SQDIFF_NORMED` | 上式除以 `√(ΣT²·ΣI²)` | **最小** | 是 | 归一化后对亮度线性变化鲁棒。**实践中用这个** |
| `TM_CCORR` | `Σ(T·I)` | 最大 | 否 | 互相关。亮度高的区域天然得分高，**容易误检** |
| `TM_CCORR_NORMED` | 上式除以模长 | 最大 | 是 | 归一化互相关，鲁棒性提升 |
| `TM_CCOEFF` | `Σ(T'·I')`，先减均值 | 最大 | 否 | 去均值后解决了 CCORR 的偏置问题 |
| `TM_CCOEFF_NORMED` | 上式除以模长 | 最大 | 是 | **归一化互相关（NCC）**，最常用，值域 [-1,1] |

> **关键陷阱**：`SQDIFF` 系列是**越小越好**，其余是**越大越好**。混用会导致取到最差匹配。
> 本模块的 `matchAt()` 里用 `minMaxLoc` 分了两条分支，`normScore()` 再把 SQDIFF 取反归一化，
> 保证打印出的分数**统一是"越大越好"**。

## 3. 运行

```powershell
cd build_algo_ALL\algorithms

.\algo_template_matching.exe                                                  # 默认 lena + lena_tmpl
.\algo_template_matching.exe ..\..\data\images\lena.jpg ..\..\data\lena_tmpl.jpg
```

构建：

```powershell
.\build.ps1 -Target algorithms -Module template_matching
```

## 4. 输入 / 输出

**输入**

| 参数 | 位置 | 默认 | 说明 |
|------|------|------|------|
| `argv[1]` | 场景图 | `../../data/images/lena.jpg` | 在其中搜索 |
| `argv[2]` | 模板图 | `../../data/lena_tmpl.jpg` | 应是场景图的子区域 |

- 场景图长边 > 700 px 时，场景与模板**按比例一起缩放**（保持相对尺度关系）。
- 任一读取失败 → 合成随机图并从 (80,60) 处裁 100×100 作为模板，保证可跑。

**输出**

| 文件 | 内容 |
|------|------|
| `out/algorithms/template_matching_compare.png` | 8 格 3 列：template / 6 种方法各自的匹配框（红框）/ multi-scale best（绿框 + 文字标注） |

**stdout**

```
method              score
SQDIFF                0.9412 @ (112,88)
SQDIFF_NORMED         0.9547 @ (112,88)
CCORR                 0.8813 @ (112,88)
CCORR_NORMED          0.9601 @ (112,88)
CCOEFF                0.7902 @ (112,88)
CCOEFF_NORMED         0.9633 @ (112,88)
best multi-scale: s=1.00 NCC score=0.9633 rect=(112,88,100,100)
```

## 5. 参数表

| 参数 | 代码位置 | 默认 | 影响 |
|------|---------|--------|------|
| 6 种 TM 方法 | `for (int m : {TM_SQDIFF, ...})` | 全跑 | — |
| 多尺度范围 | `for (double s = 0.5; s <= 2.01; s *= 1.3)` | `0.5 → 2.0` | 搜索的尺度区间 |
| 尺度步长 | 同上 | `×1.3` | **几何级数**扫描。步长↓ 精度高但慢 |
| 多尺度用哪些方法 | `{TM_CCOEFF_NORMED, TM_CCORR_NORMED}` | 只跑 2 种归一化方法 | 归一化方法在不同尺度间分数才可比 |
| 尺度下限 | `if (tw < 8 \|\| th < 8 ...)` continue | `8` px | 太小的模板没有区分度 |
| 尺度上限 | `tw > scene.cols \|\| th > scene.rows` | 不超过场景 | 模板不能比场景还大 |
| 缩放插值 | `resize(..., INTER_LINEAR)` | 线性 | 缩小模板用 `INTER_AREA` 更合适 |

## 6. 依赖数据

| 数据 | 路径 | 说明 |
|------|------|------|
| 默认场景图 | `data/images/lena.jpg` | **`data/` 为只读依赖，禁止修改** |
| 默认模板图 | `data/lena_tmpl.jpg` | lena 的子区域 |

> **自制模板的方法**：用任意看图工具从场景图里裁一块存成新文件即可。
> 注意模板要包含**足够多的结构信息**——纯色块没有区分度，匹配结果会很平（到处都是高分）。

## 7. 结果怎么读

### 7.1 分数表

`score` 已统一归一化为"越大越好"（SQDIFF 系列做了 `1 − s` 取反），所以可以横向比较。

| 现象 | 诊断 |
|------|------|
| 6 种方法的 `loc` 完全一致 | 目标明确、区分度高，匹配成功 |
| `CCORR` 的 loc 与其他 5 个不同 | **典型的 CCORR 失效**——它倾向于匹配到图像最亮的区域。这也是为什么实践中不用裸 CCORR |
| `SQDIFF` 分数明显低于归一化版本 | 场景与模板存在亮度差异，归一化方法更鲁棒 |
| 所有方法分数都很高（>0.95）但 loc 乱 | 模板区分度不够（如纯色块/重复纹理），换个结构丰富的模板 |

### 7.2 多尺度结果

`multi-scale best` 面板上会标注最优的 `s`（尺度）、方法（NCC / NCCor）和分数，
绿框就是最终定位。

**判读**：

- `s ≈ 1.00` → 模板尺度就是对的，多尺度扫描只是确认了一遍。
- `s` 明显偏离 1 → 说明模板与场景中的目标存在**尺度差异**，单尺度匹配必然失败，
  这正是多尺度的价值。
- 如果最优 `s` 恰好落在扫描区间边界（0.5 或 2.0），说明**真实尺度在范围外**，需放宽区间。

### 7.3 模板匹配的硬限制

模板匹配只能处理**平移**（+ 本模块额外的尺度）。以下情况会失败，应改用特征匹配
（见 `feature_detection` 模块）：

- 目标发生**旋转** → 需要在角度维度也扫描（代价高），或改用带旋转不变性的 ORB/AKAZE
- 目标发生**透视/仿射形变** → 模板匹配无能为力
- 光照剧烈变化 → 归一化方法能扛住线性变化，扛不住非线性
- 目标被**部分遮挡** → 用 `TM_CCOEFF_NORMED` 加掩膜（`matchTemplate` 的 `mask` 参数）可部分缓解
