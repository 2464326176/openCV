# inpaint —— 图像修复（划痕 / 遮挡去除）

## 1. 功能概述

对干净图**人为制造损伤**（随机划痕 + 一块文本遮挡块），用两种经典修复算法复原，
并给出**整图 PSNR** 与 **遮挡区 MAE** 两个互补指标。

因为损伤是我们自己加的，所以有**完整 GT（干净原图）**——这让本模块可以做真正的定量评估，
而不是靠肉眼说"看起来还行"。

## 2. 算法清单

| 算法 | 枚举 | 原理 | 特点 |
|------|------|------|------|
| **Telea** | `INPAINT_TELEA` | **Fast Marching Method（快速步进法）**。从受损区域边界出发，按到边界的距离由近及远逐像素填充，用邻域已知像素的加权和（沿等照度线方向传播） | 速度快，**倾向于沿边缘方向"抹平"**，对细划痕效果极佳 |
| **Navier-Stokes** | `INPAINT_NS` | 基于**流体力学**的偏微分方程。把图像灰度视为"流函数"，沿等照度线方向传导（各向异性扩散），同时用拉普拉斯项保持平滑 | 速度慢些，**边缘连续性更好**，大面积区域更自然 |

> **共同思想**：都是**沿等照度线（isophote）方向传播信息**——让结构线自然延续进待修复区，
> 而不是简单地做邻域模糊。这也是修复与"高斯糊一下"的本质区别。

## 3. 运行

```powershell
cd build\algorithms

.\inpaint.exe                                    # 默认 data/images/lena.jpg
.\inpaint.exe ..\..\data\images\VCG5.jpg
```

构建：

```powershell
.\build.ps1 -Target algorithms -Module inpaint
```

## 4. 输入 / 输出

**输入**

| 参数 | 位置 | 默认 | 说明 |
|------|------|------|------|
| `argv[1]` | 干净底图 | `../../data/images/lena.jpg` | 会被人为损伤，同时作为评估 GT |

- 长边 > 520 px 自动缩放到 520。
- 读取失败时合成随机图兜底。

**损伤合成**（`drawDamage()`，固定 RNG 种子 12345，**结果可复现**）：

| 类型 | 参数 | 说明 |
|------|------|------|
| 划痕 | 5 条随机细线，`line(..., 2px)` | 白色，长度方向随机 ±150/±60，mask 用 3px 描（比可见划痕略宽，确保全覆盖） |
| 文本块 | `Rect(30, 30, 180, 46)` | 白色填充 + 黑色 "HELP?" 文字，模拟字幕/水印遮挡 |

**输出**

| 文件 | 内容 |
|------|------|
| `out/algorithms/inpaint_compare.png` | 7 格 3 列：clean(ref) / damaged / mask / TELEA r=3 / TELEA r=8 / NS r=3 / NS r=8 |

**stdout**

```
damaged pixels = 3.41%
method      wholePSNR    maskMAE
TELEA r=3        34.12       8.7
TELEA r=8        33.85       9.1
NS r=3           34.31       8.2
NS r=8           33.90       8.8
```

## 5. 参数表

| 参数 | 代码位置 | 默认值 | 影响 |
|------|------|------|------|
| 修复算法 | `for (int method : {INPAINT_TELEA, INPAINT_NS})` | 两种都跑 | — |
| 修复半径 `r` | `cv::inpaint(damaged, mask, out, r, method)` | `3` / `8` | **每个像素考虑邻域的半径（像素）**。见下方说明 |
| RNG 种子 | `cv::RNG rng(12345)` | `12345` | 固定种子保证损伤可复现，便于跨版本比较 |
| 划痕数量 | `for (int i = 0; i < 5; ++i)` | `5` | 增加划痕 → 遮挡率上升，修复难度上升 |
| mask 阈值 | `mask` 里 `255` 表示受损 | — | `inpaint` 只认非零像素为待修复区 |

**`r` 怎么选**：

```
r 必须 ≥ 待修复区域的"最大宽度 / 2"
```

- 细划痕（2~3 px 宽）→ `r=3` 足够，甚至 `r=2`。
- 大块遮挡（如 46 px 高的文字块）→ `r=8` 都不够，需要 `r=15+`。
- **r 过大会导致**：耗时增加 + 过度扩散使修复区糊掉。
- **r 过小会导致**：修复区填充不完整，残留原来的白色（因为传播距离不够）。

本模块默认只扫 `r ∈ {3, 8}`，主要用于演示趋势。真实用大遮挡时建议手动加大 `r`。

## 6. 依赖数据

| 数据 | 路径 | 说明 |
|------|------|------|
| 默认底图 | `data/images/lena.jpg` | **`data/` 为只读依赖，禁止修改**。损伤是**在内存中合成**的，不落盘，绝不改动原图 |

## 7. 结果怎么读

两个指标**互补**，必须一起看：

| 指标 | 定义 | 关注点 |
|------|------|--------|
| **wholePSNR** | 整张修复图 vs 干净图的 PSNR | 衡量**整体内容保持度**。因为只有 ~3% 像素受损，这个数主要由未受损区决定，区分度有限 |
| **maskMAE** | **仅在 mask 区域内**的平均绝对误差 | **核心指标**。直接衡量"修复区填得像不像" |

> 注意 `wholePSNR` 的"稀释效应"：遮挡率只有 3%，即使修复区完全失败，整图 PSNR 也不会
> 掉太多。所以**判断修复质量要看 maskMAE，不要被 wholePSNR 骗了**。

**典型观察**：

- **maskMAE 通常在 8~12 之间**（0~255 尺度），说明修复区与原图平均差 8~12 个灰阶——
  视觉上基本看不出来，但也不算完美复原（毕竟信息是真的丢了）。
- **NS 在边缘连续的区域略优于 Telea**（maskMAE 更低），因为它的各向异性扩散更"执着"于延续结构线。
- **Telea 在细划痕上更快且效果相当**，是实时场景的首选。
- `r=3` 通常优于 `r=8`：本 demo 的划痕很细，半径大了反而把周围正常像素的信息"搅"进来，
  引入不必要的平滑。**这印证了 r 要与损伤尺度匹配**。

**视觉检查清单**：

| 现象 | 说明 |
|------|------|
| 修复区残留白色块 | `r` 太小，信息没传播到中心。加大 `r` |
| 修复区糊成一团、纹理消失 | `r` 太大，或算法在高纹理区无能为力（信息本来就不存在） |
| 划痕修复后留下淡淡的线 | 正常。等照度线传播无法凭空造出被完全覆盖的纹理 |
| 文本块区域变成一片色块 | 大区域修复的固有问题。真实需求应改用**生成式修复**（见 TODO） |
